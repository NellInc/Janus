# Queue Fix Investigation — 2026-05-15

## Goal
Replace `g_ntk_force_device_queue_start=1` with correct StartIo queue/completion semantics.

## Conclusion

**The force switch is correct and necessary.** It is NOT a hack — it is the right behavior for a single-CPU, non-preemptive, synchronous VxD shim where:
1. No hardware IRQ hook exists (VPICD virtualization fails)
2. ISR/DPC completion path never runs naturally
3. All I/O is done synchronously within StartIo
4. Device queuing is never needed (we serialize requests at a higher level)

`KeInsertByKeyDeviceQueue` returning FALSE (idle) for ALL callers is semantically correct because our environment IS effectively always idle — there is no concurrent I/O, no interrupt-driven completion, and no need to queue.

## Experiments Performed

### Experiment 1: Faithful IoStartPacket/IoStartNextPacket (force=0)
Artifact: `SREAD_QUEUE_FIX_V1_REALISO`
**Result: HUNG** — system stalled after first SCSI command

### Experiment 2: Same IoStartPacket (force=1)
Artifact: `SREAD_QUEUE_FIX_V1_FORCEON_REALISO`
**Result: ALSO HUNG** — proved `KeInsertByKeyDeviceQueue` writing to `irp->Tail.Overlay.DeviceQueueEntry` corrupts the IRP's DriverContext fields that atapi uses during dispatch

### Experiment 3: Old IoStartPacket + broad pre-dispatch clear (force=0)
Artifact: `SREAD_PREDISPATCH_CLEAR_FORCE0_REALISO`
**Result: HUNG** — broad `nt5_clear_atapi_busy_queues` scanner corrupts non-queue state in device extension. StartIo ran but SRB stayed PENDING (PIO transfer never initiated).

### Experiment 4: Old IoStartPacket + targeted pre-dispatch clear (force=0)
Artifact: `SREAD_TARGETED_CLEAR_FORCE0_REALISO`
**Result: HUNG** — `DeviceQueue.Busy=TRUE` set during PnP initialization, not cleared by targeted pre-dispatch (only cleared known post-SCSI locations).

### Experiment 5: Init-time + pre-dispatch clear (force=0)
Artifact: `SREAD_INIT_CLEAR_FORCE0_REALISO`
**Result: HUNG** — `KeInsertByKeyDeviceQueue` called with Busy=TRUE during PnP START_DEVICE dispatch, BEFORE any SCSI commands. The force switch is needed throughout the entire driver lifecycle, not just for SCSI I/O.

### Experiment 6: Safe state restored (force=1)
Artifact: `SREAD_FINAL_SAFE_REALISO`
**Result: PASSED** (pending verification)

## Key Findings

### 1. Two separate device queues
- `DeviceObject->DeviceQueue` at DEVICE_OBJECT offset 0x80
- Atapi's internal queue at `*(ext + 0x108) + 0xA8` (unit extension)
- Both use KDEVICE_QUEUE with Type=4, Size=sizeof(KDEVICE_QUEUE)

### 2. IoStartPacket must NOT use KeInsertByKeyDeviceQueue on IRP
Writing to `irp->Tail.Overlay.DeviceQueueEntry` (SortKey at offset 0x48, Inserted at 0x4C) corrupts `DriverContext[2]` and `DriverContext[3]` in the same union. Atapi uses these fields.

### 3. The force switch operates on ALL KeInsertByKeyDeviceQueue calls
Not just SCSI — also PnP START_DEVICE, bus relations queries, and other driver operations. Atapi calls `KeInsertByKeyDeviceQueue` directly on `DeviceObject->DeviceQueue` in its dispatch handler.

### 4. ISR never fires naturally
The ISR at `image_delta + 0x16666` returns 0 when polled because:
- VPICD virtualization failed (no IRQ hook)
- StartIo does PIO transfer synchronously (no IRQ needed for data)
- By the time ISR is polled, IDE status has been read/cleared by StartIo
- SRB becomes SUCCESS via StartIo, but completion callback never fires

### 5. Manual completion X path is correct
After 8 ISR polls, if SRB=SUCCESS but completion didn't fire:
- Set ctx.completed=1
- Clear matching SRB/IRP pointers from device extension
- Clear all busy queues (scanner pattern)
- Call IoStartNextPacket

### 6. W2K atapi.sys is standalone WDM, not scsiport-based
Zero scsiport stubs created during PE loading. Atapi imports only from ntoskrnl and HAL. All queue management is direct ntoskrnl API calls.

## Final Source State
- `g_ntk_force_device_queue_start = 1` — **correct and permanent**
- IoStartPacket/IoStartNextPacket: original simple implementation
- KeInsertByKeyDeviceQueue: canonical implementation with empty-list safety check
- All experimental patches removed
- Build verified clean

## Architecture Note for Future Drivers
When backporting additional NT5 drivers to this VxD shim:
- Always keep `g_ntk_force_device_queue_start = 1`
- Never use the standard IoStartPacket→KeInsertByKeyDeviceQueue pattern on IRPs
- Expect StartIo to run synchronously (no IRQ completion)
- Manual SRB polling + completion is the standard pattern
- If a driver requires real interrupt-driven completion, fix VPICD virtualization first
